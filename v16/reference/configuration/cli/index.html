    CLI Reference¶

    This page lists every bench command that the frappe app adds, in this version. The list and the options come from the click definitions in frappe/commands/ and the Studio and Flow command modules. Commands of the bench tool itself (init, get-app, new-app, start, setup ...) are not on this page. Run all commands from the bench root (frappe-bench/).

    How commands find the site¶

    bench loads frappe.commands.commands and the commands list of every other app (<app>/commands/__init__.py or <app>/commands.py). It wraps them in one group that takes these options before the command name:

    Option Description
    --site <site> Site to run on. --site all runs on every site, for commands that loop over sites.
    --verbose Verbose output.
    --force Force flag. Some commands read it (for example run-patch, reload-doc).
    --profile Run the command under cProfile and print the top 100 lines.

    When --site is not given, bench uses the FRAPPE_SITE environment variable, then default_site from common_site_config.json (set with bench use <site>).

    bench --site frappe.localhost migrate
bench --site all clear-cache
bench --site frappe.localhost execute frappe.client.get_count --args '["ToDo"]'

    In the tables below, "Needs site" means:

    • Yes: the command runs on the site from --site (or the default site). Without one, it fails with "Please specify --site sitename".
    • Optional: the command also works without a site, or takes --site after the command name.
    • No: the command does not use a site.

    Run bench <command> --help to see the same options on your bench. Commands in a group (flow-server) take the subcommand next: bench flow-server status.

    Sites and apps¶

    Defined in frappe/commands/site.py.

    Command Needs site Description
    add-system-manager Yes Add a new system manager to a site.
    add-user Yes Add user to a site.
    add-database-index Yes Adds a new DB index and creates a property setter to persist it.
    describe-database-table Yes Show the schema, indexes and row count of a DocType table as JSON. With --column, also show distinct value counts.
    backup Yes Make a database backup of the site. Optionally include files and config.
    drop-site No (<site> argument) Remove a site from database and filesystem.
    install-app Yes Install a new app to site, supports multiple apps.
    list-apps Yes List apps in site.
    migrate Yes Run patches, sync schema and rebuild files/translations.
    migrate-to No Move a site to a hosting provider (Frappe Cloud). Interactive.
    new-site No (<site> argument) Create a new site.
    reinstall Yes Reinstall site ie. wipe all data and start over.
    reload-doc Yes Reload schema for a DocType.
    reload-doctype Yes Reload schema for a DocType.
    remove-from-installed-apps Yes Remove app from site's installed-apps list.
    restore Yes Restore site database from an sql file.
    run-patch Yes Run a particular patch.
    set-password Yes Set password for a user on a site.
    set-admin-password Yes Set Administrator password for a site.
    uninstall-app Yes Remove app and linked modules from site.
    disable-user Yes Disable a user account on site.
    use No (<site> argument) Set a default site.
    set-last-active-for-user Yes Set users last active date to current datetime.
    publish-realtime Yes Publish realtime event from bench.
    browse Optional Open the site in a web browser, logged in as a user.
    start-recording Yes Start Frappe Recorder.
    stop-recording Yes Stop Frappe Recorder.
    add-to-hosts Yes Add the site name to /etc/hosts (uses sudo).
    ngrok Yes Start a ngrok tunnel to your local development server.
    build-search-index Yes Build the full text search index of website routes (frappe/search/website_search.py).
    partial-restore Yes Restore some tables from a partial backup file (made with backup --only). Not supported on SQLite.
    trim-tables Yes Remove columns from tables where fields are deleted from doctypes.
    trim-database Yes Remove database tables for deleted DocTypes.
    clear-log-table Yes Shrink a large log table. Recent rows are copied to a new table, which replaces the old one.
    bypass-patch Yes Bypass a patch permanently instead of migrating using the --skip-failing flag.
    sync-desktop-icons Yes Import the desktop icon fixtures again for the site.

    add-system-manager¶

    bench --site <site> add-system-manager [OPTIONS] EMAIL
    Option Default Description
    --first-name First name of the user.
    --last-name Last name of the user.
    --password Password of the user.
    --send-welcome-email off Send the welcome email.

    add-user¶

    bench --site <site> add-user [OPTIONS] EMAIL
    Option Default Description
    --first-name First name of the user.
    --last-name Last name of the user.
    --password Password of the user.
    --user-type User type, for example System User.
    --add-role Role to add. Repeat for many values.
    --send-welcome-email off Send the welcome email.

    add-database-index¶

    bench --site <site> add-database-index [OPTIONS]
    Option Default Description
    --doctype DocType on which index needs to be added.
    --column Column to index. Multiple columns will create multi-column index in given order. To create a multiple, single column index, execute the command multiple times. Repeat for many values.

    describe-database-table¶

    bench --site <site> describe-database-table [OPTIONS]
    Option Default Description
    --doctype DocType to describe.
    --column Explicitly fetch accurate cardinality from table data. This can be quite slow on large tables. Repeat for many values.

    backup¶

    bench --site <site> backup [OPTIONS]
    Option Default Description
    --with-files off Take backup with files.
    --include, --only, -i Specify the DocTypes to backup separated by commas.
    --exclude, -e Specify the DocTypes to not backup separated by commas.
    --backup-path Set path for saving all the files in this operation.
    --backup-path-db Set path for saving database file.
    --backup-path-files Set path for saving public file.
    --backup-path-private-files Set path for saving private file.
    --backup-path-conf Set path for saving config file.
    --ignore-backup-conf off Ignore excludes/includes set in config.
    --verbose off Add verbosity.
    --compress off Compress private and public files.
    --old-backup-metadata off Use older backup metadata.

    drop-site¶

    bench drop-site [OPTIONS] SITE
    Option Default Description
    --db-root-username, --mariadb-root-username, --root-login Root username for MariaDB or PostgreSQL, Default is "root".
    --db-root-password, --mariadb-root-password, --root-password Root password for MariaDB or PostgreSQL.
    --archived-sites-path Folder for the archived site. Default <bench>/archived/sites.
    --no-backup off Do not take a backup before the drop.
    --force off Force drop-site even if an error is encountered.

    new-site¶

    bench new-site [OPTIONS] SITE
    Option Default Description
    --db-name Database name.
    --db-password Database password.
    --db-type mariadb Optional "sqlite", "postgres" or "mariadb". Default is "mariadb". One of mariadb, postgres, sqlite.
    --db-host Database Host.
    --db-port Database Port.
    --db-root-username, --mariadb-root-username Root username for MariaDB or PostgreSQL, Default is "root".
    --db-root-password, --mariadb-root-password Root password for MariaDB or PostgreSQL.
    --db-socket, --mariadb-db-socket Database socket for MariaDB or folder containing database socket for PostgreSQL.
    --no-mariadb-socket off DEPRECATED: Set MariaDB host to % and use TCP/IP Socket instead of using the UNIX Socket.
    --mariadb-user-host-login-scope Set the mariadb host for the user login scope if you do not want to use the current host as login scope which typically is ''@'localhost' - may be used when initializing a user on a remote host. See the mariadb docs on account names for more info.
    --admin-password Administrator password for new site.
    --verbose off Verbose.
    --force off Force restore if site/database already exists.
    --source-sql, --source_sql Initiate database with a SQL file.
    --install-app Install app after installation. Repeat for many values.
    --set-default off Set the new site as default site.
    --setup-db, --no-setup-db off Create the user and database in MariaDB or PostgreSQL. When false, only bootstrap.
    --db-user Database user if you already have one.

    restore¶

    bench --site <site> restore [OPTIONS] SQL_FILE_PATH
    Option Default Description
    --db-root-username, --mariadb-root-username Root username for MariaDB or PostgreSQL, Default is "root".
    --db-root-password, --mariadb-root-password Root password for MariaDB or PostgreSQL.
    --db-name Database name for site in case it is a new one.

    --with-private-files Restores the private files of the site, given path to its tar file.
    --force off Ignore the validations and downgrade warnings. This action is not recommended.
    --encryption-key Backup encryption key.

    Scheduler and workers¶

    Defined in frappe/commands/scheduler.py.

    Command Needs site Description
    disable-scheduler Yes Disable scheduler.
    doctor Optional Show diagnostic info about the scheduler and background workers.
    enable-scheduler Yes Enable scheduler.
    purge-jobs Optional Delete pending jobs from the queues. Without --event, it deletes all jobs of the site.
    ready-for-migration Yes Exit with code 1 when the site has pending background jobs. Use it before a migrate.
    scheduler Yes Control the scheduler. STATE is one of pause, resume, disable, enable, status.
    set-maintenance-mode Yes Put the site in maintenance mode, or take it out. STATE is on or off.
    show-pending-jobs Yes Get diagnostic info about background jobs.
    schedule No Start scheduler process which is responsible for enqueueing the scheduled job types.
    worker No Start a background worker.
    worker-pool No Start a pool of background workers.
    trigger-scheduler-event Yes Trigger a scheduler event.

    worker¶

    bench worker [OPTIONS]
    Option Default Description
    --queue Queue to consume from. Multiple queues can be specified using comma-separated string. If not specified all queues are consumed.
    --quiet off Hide Log Outputs.
    -u, --rq-username Redis ACL user.
    -p, --rq-password Redis ACL user password.
    --burst off Run Worker in Burst mode.
    --strategy Dequeuing strategy to use. One of round_robin, random.

    worker-pool¶

    bench worker-pool [OPTIONS]
    Option Default Description
    --queue Queue to consume from. Multiple queues can be specified using comma-separated string. If not specified all queues are consumed.
    --num-workers 2 Number of workers to spawn in pool.
    --quiet off Hide Log Outputs.
    --burst off Run Worker in Burst mode.

    Utilities¶

    Defined in frappe/commands/utils.py.

    Command Needs site Description
    build No Compile JS and CSS source files.
    clear-cache Yes Clear cache, doctype cache and defaults.
    clear-website-cache Yes Clear website cache.
    convert-sidebar-fixtures Yes Convert an app's old workspace_sidebar fixtures into per-module Sidebar exports.
    db-console Yes Enter into the Database console for given site.
    transform-database Yes Change tables' internal settings changing engine and row formats.
    jupyter Yes Start an interactive jupyter notebook.
    console Yes Start ipython console for a site.
    destroy-all-sessions Yes Clear sessions of all users (logs them out).
    execute Yes Run a Python function on the site. Prints the return value.
    export-csv Yes Export data import template with data for DocType.
    export-doc Yes Export a single document to csv.
    export-fixtures Yes Export fixtures.
    export-json Yes Export doclist as json to the given path, use '-' as name for Singles.
    version No Show the versions of all the installed apps.
    data-import Yes Import documents in bulk from CSV or XLSX using data import.
    import-doc Yes Import (insert/update) doclist. If the argument is a directory, all files ending with .json are imported.
    make-app No Creates a boilerplate app.
    create-patch No Make a new patch file and add it to patches.txt. Interactive.

    Pitfalls¶

    • Put global options before the command: bench --site s1 migrate, not bench migrate --site s1. Only commands that define their own --site (for example doctor, show-pending-jobs, build-studio-app) accept it after the name.
    • bench execute evaluates --args and --kwargs as Python literals. Quote them for the shell.
    • restore, reinstall, drop-site and uninstall-app delete data. Take a backup first.
